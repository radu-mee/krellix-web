## 1. Performance

### High
1. **Hero images are huge SVGs that wrap embedded PNG/JPEG data.** For example, `home-hero-image-*-eng.svg` is 2.86 MB raw and 1.96 MB gzipped. One embedded raster in it is 1.68 MB of base64. About 30 files in `public/images` are 0.8–2.9 MB each.
   - Fix: export real AVIF/WebP rasters at 1x and 2x, about 80–200 KB each. Serve them with `<picture>`/`srcset`, or with `image-set()` in the CSS rules at `app/globals.css:247-281`.
   - **Done (2026-11-25), using a different approach that keeps quality.**
     - The files stay SVG, so text stays vector-sharp. Only the PNG/JPEG pictures Figma embeds inside them are re-encoded as WebP (q90, full alpha quality), with `npm run images:optimize` (`scripts/images/optimize-svg-rasters.mjs`).
     - 48 files changed: 55 MB → 16.8 MB on disk, and 34.3 MB → 6.2 MB over the wire with brotli. For example, the home hero went from 1.9 MB to 256 KB.
     - Verified in the browser at 2x: every file is visually identical to its original. At most 0.0013% of pixels differ noticeably, and the largest single difference is 19 out of 255.
     - Run the script on every new Figma export. Files under 20 KB, such as the favicon, are skipped.
2. **The LCP image is lazy-loaded on `/product` and `/solutions/*`.** The top hero (`product-chat-image-*`, `solutions-*-hero-image-*`) renders with `loading="lazy"`. Meanwhile, below-the-fold illustrations on solution pages get `<link rel=preload>`. The priority is inverted.
   - Fix: pass `priority`/eager on the first hero and drop it from the illustrations below.
3. **The middleware sets `Set-Cookie` on every response** (`middleware.ts:64-73`), even when the cookie already exists. Cloudflare won't cache responses that carry `Set-Cookie`, so every HTML hit goes to the Worker.
   - Fix: set it only when it's missing or changed.
4. **Some pages are rendered on every request.** `/en/blog` and `/en/resources/{agents,guides,templates}` read `searchParams.page`, so they are **not** prerendered. I confirmed in `.next/prerender-manifest.json` that they're missing, even though the build table shows ● for them.
   - Fix: drop `?page` (every index fits on one page except the blog), or use `/blog/page/[n]` with `generateStaticParams`.

### Medium
5. **Logos are preloaded twice at high priority.** `ui/ThemeImage.tsx:37-39` puts `fetchPriority="high"` and eager loading on both the light and dark `<img>`. With the footer logo also passing `priority`, that's 4 high-priority image requests competing with the hero.
   - Fix: inline the logo SVG with `currentColor`, or drop the priority.
6. **The ASCII canvas animations are expensive:**
   - Each glyph is drawn twice, once with `shadowBlur` (`AsciiEffectDemo.tsx:383-393`, `Ascii404Burst.tsx:203-213`).
   - The loop keeps waking every frame while hidden.
   - The visibility handler sets `isVisible = true` even when the canvas is off-screen (`Ascii404Burst.tsx:240`, `AsciiEffectDemo.tsx:420`).
   - Reduced motion still animates them, just slower.
   - Fix: reuse the `syncPlayback` pattern from `HomeHeroGlyphPulse.tsx:156-164` and use a CSS `drop-shadow` for the glow.
7. **The new `HomeHeroGlyphPulse` draws about 4–5k glyphs per frame at about 33 fps**, and the fixed header with `backdrop-blur` sits over it. Its pause and reduced-motion handling is the best in the codebase. Consider about 20 fps, or a pre-rendered glyph atlas.
8. **Canvas fonts may be inconsistent.**
   - `HomeHeroGlyphPulse.tsx:83` uses Cascadia/Consolas, which exist on Windows only, so Mac and mobile render a different font.
   - The other canvases use `'JetBrains Mono'`. That name is correct: next/font keeps the real family name. But they don't wait for the font to load, so the first frames can draw in a fallback font.
   - Fix: use `'JetBrains Mono', monospace`, and await `document.fonts.load()` before the first paint.
   - Correction: an earlier draft said next/font hashes the family name. It doesn't.
9. **The heading font flashes on first load.** Reported by the user: the H1 shows in a different font for a split second, then switches. Three causes, all confirmed in the build output:
   - **`display: "swap"`** (`app/layout.tsx:8-20`) tells the browser to show text in a fallback font immediately and swap when the real font arrives. That swap is the flash.
   - **The fonts are never preloaded.** The page HTML has no `<link rel="preload" as="font">`, locally or on the live site. `.next/server/next-font-manifest.json` is empty (`"app": {}`), so Next.js doesn't know which fonts each page uses. The browser only finds the font after it downloads and parses the CSS, which makes the swap later and more visible.
     - **Root cause (confirmed): a Next.js bug on Windows.** `next/dist/build/webpack/plugins/next-font-manifest-plugin.js` finds font modules with `mod.request.includes('/next-font-loader/index.js?')`, using forward slashes. On Windows the request path uses backslashes (`F:\Synology Drive content\...\next-font-loader\index.js?...`), so nothing matches. Every webpack build on Windows silently ships without font preloads. The live site is built and deployed from this Windows machine, so it's affected.
     - **Not fixed upstream.** The same check is in 15.2.9 (installed), 15.5.29 (latest 15.x) and 16.4.6 (latest), so upgrading won't fix it.
     - **Fix proven.** Normalising the slashes (`mod.request.replace(/\\/g, '/')`) in a temporary patch filled the manifest. The build then emitted 4 `<link rel="preload" as="font">` tags: JetBrains Mono 400, plus Poppins 400/500/600 (latin), about 44 KB total. The patch was reverted afterwards.
   - **The fallback for a monospace font is Arial.** The headings use JetBrains Mono, which is monospaced, but next/font's auto-generated fallback is size-adjusted Arial, which is proportional. Every letter changes width when the real font arrives, so the line visibly reflows instead of just changing slightly.
   - **Fixes, in order:**
     1. ~~Make the slash fix permanent.~~ **Done (2026-11-25):** `patches/next+15.2.9.patch` (one line) is applied by `"postinstall": "patch-package"` on every `npm install`. A clean build now fills the manifest, and `en`, `en/product` and `en/pricing` each carry 4 font preloads. When upgrading Next.js, patch-package flags the patch as stale. Either regenerate it (`npx patch-package next`) or delete it if the bug has been fixed upstream.
     2. Give JetBrains Mono a monospace fallback: `fallback: ["ui-monospace", "SFMono-Regular", "Menlo", "Consolas", "monospace"]` with `adjustFontFallback: false`.
     3. Optionally use `display: "optional"` for the heading font. It never swaps, but on a slow first visit the page may stay in the fallback font.

### What's already good
- Shared JS is only 101 kB. Only 13 client components exist, and all pages except the four above are SSG.
- Fonts load through next/font with `swap`. There's no theme flash, thanks to the blocking `ThemeScript`.
- Hidden lazy theme variants aren't downloaded. Every listener and observer is cleaned up.

## 3. Code quality and correctness bugs

### High
1. **"Your privacy choices" does nothing for non-EU visitors.** `ui/ConsentBanner.tsx:97-104` returns early, before the click listener at :148 is attached. That makes the opt-out link dead for US/CA visitors, which is a CCPA concern.
2. **The waitlist form locks out users who make a mistake.** `WaitlistHero.tsx:37` stores the rate-limit timestamp *before* the request and clears it only on network errors. A rejected submission (say, a typo'd email) blocks a retry for 60 s with a "Too many signups" message. Any "Failed to fetch", including being offline, also shows "Too many signups".
3. **Social cards show the generic site title on about 65 pages.** The root `openGraph`/`twitter` in `app/layout.tsx:46-63` gives them the title "Krellix", a generic description and no `og:url`. Only blog posts override it.
   - Fix: a `buildPageMetadata()` helper in `lib/seo.ts`, used by every page.
4. **Blog index links redirect.** `BlogIndexContent.tsx:31` uses `/blog/${slug}` without the locale, so every click and every crawl goes through a 308 redirect. Fix: wrap it with `localizePath()`.

### Medium
5. **The consent region list is incomplete.** It covers EU-27 only and misses GB, NO, IS, LI and CH (`middleware.ts:9-37`). Rejecting consent doesn't clear existing `_ga*` cookies.
6. **Discovery files advertise endpoints that don't exist:** `/mcp`, `/en/developers` and `/api/openapi.json`. They appear in `.well-known/*` and in the `Link` header sent on every response (`next.config.ts:23`).
7. **The sitemap reports false freshness.** It sets `lastModified: new Date()` on every static route, so each deploy claims every page changed, and IndexNow resubmits them all. Also, `/registration-successful` is in the sitemap and indexable.
8. **Copy bug:** the answer to "What is AI for developers?" starts with "Yes. AI code review…" and duplicates the next answer (`SolutionDevelopersContent.tsx:70-72`).
9. **Placeholder copy remains on error pages.** `app/error.tsx` still says "scaffold… legal-page sample", and `not-found.tsx` has the typo "Oups!". There's no `global-error.tsx`.
10. **Inline styles break the project's own rule.** There are 45 copies of `style={{ color: "#BA88FF" }}`. Make it a Tailwind token.

### Low
- **Accessibility:**
  - The waitlist input has `outline-none` and no focus ring, and its error has no `role="alert"`.
  - Neither the mobile menu nor the consent dialog moves focus into itself or closes on Escape.
  - `scroll-behavior: smooth` ignores reduced motion.
  - `ThemeImage` with `alt=""` still gets `role="img"`.
- **`ThemeToggle`** starts as "dark" and visibly slides on load for light-theme users.
- **`CurrentYear`** shows the build year on static pages, so being a client component gains nothing.
- **`localStorage` calls aren't wrapped** in `ThemeScript` and `WaitlistHero`, so they throw when storage is blocked.
- **The cookie-policy link in `ConsentBanner` is hard-coded to `/en`.**
